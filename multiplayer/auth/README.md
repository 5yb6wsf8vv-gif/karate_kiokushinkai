# Онлайн-аккаунты: подключение с нуля

Реализованы вход/регистрация по одноразовому коду на почту, вход VK ID с PKCE и обязательный выбор курса 1–4. Ссылка «Мой аккаунт» находится сверху сайта. Для VK курс запрашивается после подтверждения личности. Имя подставляется в форму поединка. Обучение без регистрации доступно.

Профили и сессии хранятся в SQLite на сервере. Прогресс, XP и скины всё ещё локальные, без синхронизации и привязки к аккаунту. Общий компьютер использует один учебный прогресс; выход из аккаунта его не очищает. Сам вход не подтверждает авторство прежних результатов или владение локальными скинами.

## Что осталось подключить владельцу

Нужны собственный отправляющий почтовый домен с доступом к DNS, аккаунт Resend и веб-приложение VK ID. Регистрация внешних аккаунтов, настройка DNS и реальные письма/вход ВК из этой среды не выполнялись. Тесты используют подставную доставку и ответы VK ID. Не размещайте ключи в GitHub, переписке или переменных с префиксом VITE_.

### 1. Сервер и постоянное хранилище

Сервер может работать на том же хостинге, что и поединки; Render не обязателен. Нужны Node.js 22.16+ или 24, HTTPS и постоянная папка для SQLite. На временной файловой системе аккаунты потеряются при пересоздании сервиса. Бесплатный Render без постоянного диска для этих аккаунтов не подходит.

Для проверки в имеющемся Codespaces:

```bash
git pull --ff-only
npm ci
cp .env.example .env
```

Откройте `.env` и заполните значения. Файл исключён из Git. `AUTH_DB_PATH=./data/accounts.sqlite` подходит для Codespaces: остановка процесса сохраняет базу, удаление Codespace её удалит. Для постоянного сайта задайте путь к примонтированному постоянному диску. SQLite-файлы содержат персональные данные; ограничьте доступ к диску и делайте резервные копии SQLite через backup API либо после остановки сервера (учитывая WAL).

Остановите старый сервер Ctrl+C, затем:

```bash
PORT=3001 node --env-file=.env multiplayer/server.js
```

Сделайте порт 3001 публичным. `/auth/config` должен вернуть `{"email":true,"vk":true}`, когда оба способа настроены. `/health` проверяет доступность сервера, но не доставку писем и не настройку VK ID.

### 2. Отправка кодов на почту

1. В [Resend](https://resend.com/) создайте аккаунт и добавьте свой домен в Domains.
2. Внесите указанные сервисом DNS-записи и дождитесь Verified.
3. Создайте API key для отправки и сохраните на сервере как `RESEND_API_KEY`.
4. Укажите `AUTH_EMAIL_FROM`, например `Киокушинкай <login@ваш-домен.ru>`.
5. Перезапустите сервер, запросите код на собственную почту и проверьте письмо. Тестовый домен Resend не подходит для писем всем игрокам.

Код действует 10 минут, хранится только в виде хеша, допускает 5 попыток и используется один раз. Новый код можно запросить через минуту. Пароли не собираются. Ограничения частоты по IP рассчитаны на один процесс; перед масштабированием потребуется общий лимитер.

### 3. VK ID

1. В [кабинете VK ID](https://id.vk.com/about/business/go) создайте веб-приложение для сайта.
2. Укажите домен сайта `5yb6wsf8vv-gif.github.io` и разрешённый redirect URI **точно** `https://5yb6wsf8vv-gif.github.io/karate_kiokushinkai/`.
3. Сохраните Client ID как `VK_CLIENT_ID` на сервере. В `.env` задайте `PUBLIC_APP_URL` равным этому redirect URI. Client secret для этого PKCE-потока не используется.
4. При необходимости настройте доступ приложения для пользователей в кабинете VK ID.
5. Перезапустите сервер. Проверьте реальный вход через ВК, отмену входа и выбор курса после возврата. Если VK отклоняет вход, проверьте разрешённый URI и параметры приложения в кабинете.

Используется VK ID, не устаревшая авторизация oauth.vk.com. Сервер обменивает одноразовый код с PKCE, проверяет идентификатор пользователя через user_info; access token VK не передаётся браузеру. Состояние входа одноразовое, ограничено 10 минутами и сверяется в браузере. VK-аккаунты не объединяются по неподтверждённому адресу почты.

### 4. Подключение опубликованного сайта

В GitHub откройте репозиторий → Settings → Secrets and variables → Actions → **Variables** → New repository variable:

- Name: `VITE_API_URL`
- Value: публичный HTTPS-адрес сервера **без** `/health` и `/auth`, например адрес порта Codespaces.

В Actions запустите Publish GitHub Pages → Run workflow. Сборка прочитает эту публичную переменную. Почтовые ключи туда добавлять не нужно: они остаются только на сервере. Пока переменная не задана, аккаунты используют ранее сохранённый на устройстве адрес сервера поединков; у новых посетителей вход будет недоступен. Постоянный адрес предпочтительнее временного Codespaces.

Проверьте `https://5yb6wsf8vv-gif.github.io/karate_kiokushinkai/#account` с телефона и компьютера. Вход по почте должен сохранить курс, пережить обновление страницы и позволять выйти. После перезапуска сервер должен находить прежний профиль в том же файле SQLite.

Сессия приложения действует 30 дней и отзывается при выходе. Браузер хранит её токен в localStorage; не устанавливайте на сайт сторонние скрипты, способные читать это хранилище. Для большого публичного сервиса следует перейти на размещение API и сайта под одним доменом и HttpOnly cookie. Перед публичным сбором данных разместите контакты владельца, политику обработки данных и условия хранения/удаления профилей.

## Проверки

`npm test` проверяет сроки/попытки кодов, запрет повторного использования, сохранение профиля после перезапуска, отзыв сессии, диапазон курсов, PKCE/state, методы API и CORS. `npx playwright test tests/browser/account.spec.js` проверяет форму, вход, курс, перезагрузку, изменение профиля и выход на мобильном и настольном экранах. Эти проверки не заменяют реальную отправку письма и вход через ваше VK-приложение.
