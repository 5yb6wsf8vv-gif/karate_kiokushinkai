# Подключение kihongo.ru (REG.RU → GitHub Pages)

Приложение остаётся на GitHub Pages. Для kihongo.ru не требуется покупать отдельный хостинг или SSL-сертификат. Сам домен должен быть оплачен и доступен в вашем кабинете REG.RU. Настройки ниже подготовлены в коде; доступ к вашим кабинетам DNS/GitHub из этой среды не предоставлен, поэтому DNS и Custom domain ещё нужно изменить вручную.

## 1. DNS в REG.RU

Откройте https://www.reg.ru/user/ → **Домены → kihongo.ru → DNS-серверы и управление зоной / Ресурсные записи**. Если DNS обслуживает другой сервис (посмотрите текущие NS), редактируйте записи в его панели; регистрация в REG.RU сама по себе не означает, что зона хранится у REG.RU.

Для основного имени нужны четыре записи:

| Тип | Имя / Поддомен | Значение |
| --- | --- | --- |
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | 5yb6wsf8vv-gif.github.io. |

`@` обозначает сам `kihongo.ru`. В CNAME не указывайте `https://` и `/karate_kiokushinkai/`. TTL можно оставить стандартным (например, 3600).

Замените прежние A для `@`, если они ведут на парковку регистратора или другой сайт. Не должно быть конфликтующих A/AAAA/CNAME для тех же имён. Если у `@` есть прежние AAAA, удалите или замените только их на опубликованные GitHub Pages IPv6-адреса из официальной инструкции. Не удаляйте MX/TXT и прочие записи почты или других сервисов. Не создавайте wildcard `*` для GitHub Pages.

Дождитесь применения DNS (часто минуты/часы, иногда до 24–48 часов). Официальные адреса: https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site

## 2. Указать домен в GitHub Pages

Откройте https://github.com/5yb6wsf8vv-gif/karate_kiokushinkai/settings/pages → **Custom domain** → введите `kihongo.ru` → **Save**. Нужно быть владельцем репозитория или иметь соответствующие права. После успешной проверки DNS включите **Enforce HTTPS**. Если HTTPS ещё недоступен, дождитесь выпуска сертификата GitHub и повторите проверку.

Затем **Actions → Publish GitHub Pages → Run workflow** (ветка `main`). Обновлённый workflow читает `base_path` через `actions/configure-pages`: для обычной ссылки собирает `/karate_kiokushinkai/`, для собственного домена — `/`. Поэтому ресурсы, manifest, иконки и сервис-воркер не привязаны навсегда к старой подпапке. Для публикации через GitHub Actions отдельный файл CNAME в репозитории не нужен; домен задаётся в Settings → Pages.

Ожидаемый основной адрес после проверки и публикации: **https://kihongo.ru/**. `www.kihongo.ru` будет перенаправляться на основной адрес средствами GitHub Pages. Проверьте и основной адрес, и вариант с www. До успешного подключения старую ссылку можно использовать как раньше.

## 3. Разрешить домен на сервере кумитэ

В конфигурациях Cloudflare, VPS и Node уже добавлены допустимые источники:

- `https://kihongo.ru`
- `https://www.kihongo.ru`
- прежний `https://5yb6wsf8vv-gif.github.io`

Если Worker уже опубликован, повторно опубликуйте последнюю версию из ветки `main` через Cloudflare Workers Builds или `npm run cloudflare:deploy`. Если значения ALLOWED_ORIGINS вручную переопределены в кабинете Cloudflare, добавьте туда новые источники. На VPS примените обновление конфигурации через Compose; на другом Node-хостинге обновите переменную `ALLOWED_ORIGINS` и перезапустите сервер.

Адрес API по-прежнему хранится в GitHub Actions Variable `VITE_API_URL` (HTTPS-адрес Worker без `/health`). Домен сайта `kihongo.ru` — адрес интерфейса, а не адрес API. Проверка нового сайта без работающего сервера не означает, что кумитэ подключено.

## Профиль, прогресс и установленное приложение

Браузер хранит данные отдельно для каждого origin. Прогресс, XP, скины и профиль со старого `github.io` автоматически не появляются на `kihongo.ru`. Старые данные не удаляются изменением DNS, но доступ к старому адресу после настройки Custom domain может перенаправляться на новый. Если нужно перенести уже накопленные данные, сделайте резервную копию до переключения адреса.

Установленная PWA на старом адресе не меняет свой origin на новый автоматически. После подключения домена откройте новый адрес с интернетом, дождитесь сохранения материалов и установите приложение с него. Не удаляйте данные/приложение старого адреса до сохранения нужного прогресса.

## Проверка

- DNS `kihongo.ru` возвращает адреса GitHub Pages.
- `https://kihongo.ru/` открывается без предупреждения о сертификате.
- Иконки и оформление загружаются, настройка профиля проходит, нет горизонтальной прокрутки на телефоне.
- После первого сохранения материалов приложение открывается без сети.
- Новая комната кумитэ создаётся и приглашение открывается на втором устройстве.

Проверка локальной сборки для корня домена: `npm run build -- --base /`. Сборка для старой ссылки: `npm run build -- --base /karate_kiokushinkai/`. В реальном deploy workflow выбирает этот путь по настройке GitHub Pages.
