# Постоянный сервер поединков: Timeweb Cloud с нуля

Сайт и PWA остаются на GitHub Pages. VPS круглосуточно обслуживает только поединки. Оплата и создание сервера выполняются владельцем в своём аккаунте; файлы в репозитории сами VPS не создают. Эта конфигурация не запускает прежнюю почтовую/VK-регистрацию: вход по имени и курсу остаётся локальным.

## 1. Создать VPS и найти IP

В [Timeweb Cloud](https://timeweb.cloud/) создайте облачный сервер с Ubuntu **24.04 LTS**. Для старта небольшой группы подойдёт 1 vCPU, 1 ГБ RAM и диск от 10–20 ГБ; при выборе используйте доступный размер тарифа. Нужен публичный IPv4. Перед созданием проверьте стоимость тарифа и IPv4 в кабинете.

После запуска откройте карточку этого сервера и найдите «Публичный IP» / IPv4 в информации о сервере или разделе сети. Адрес выглядит как четыре числа через точки; это **не ссылка GitHub Pages и не адрес Codespaces**. Пароль и приватный SSH-ключ не нужно передавать в переписку.

В правилах сети/файрвола разрешите входящий TCP 80 и 443 для всех посетителей. Для собственного SSH-доступа используйте порт 22 (по возможности со своего IP). Порт 3001 открывать наружу не нужно. Если ОС имеет отдельный файрвол, правила 80/443 должны быть разрешены и в нём; не меняйте правило SSH так, чтобы потерять собственный доступ.

## 2. Получить HTTPS-адрес без покупки домена

Если хостинг уже дал домен, которым вы управляете и который указывает на VPS, можно использовать его. Иначе получите бесплатный поддомен в [DuckDNS](https://www.duckdns.org/):

1. Войдите в свой аккаунт и выберите свободное имя, например `my-karate-duel.duckdns.org` (пример, доступность имени не гарантируется).
2. В поле IP укажите **IPv4 VPS из Timeweb**, а не IP своего компьютера, который сайт мог подставить автоматически.
3. Сохраните запись. IPv6 оставьте пустым, если он не настроен на VPS.
4. Подождите обновления DNS. На сервере `getent ahostsv4 ВАШ-ПОДДОМЕН.duckdns.org` должен показывать IPv4 вашего VPS.

Токен DuckDNS для работы сервера не нужен: адрес VPS обычно не меняется, запись обновляется вручную при смене IP. Токен не публикуйте. Сертификат HTTPS автоматически получает и продлевает Caddy; для этого DNS должен указывать на этот VPS, а TCP 80/443 быть доступными из интернета. Если бесплатный DNS-сервис недоступен, используйте другой управляемый поддомен или собственный домен; не переходите на HTTP на HTTPS-сайте.

## 3. Установить сервер поединков

Откройте **консоль VPS в Timeweb**, либо подключитесь к его IP через SSH. Все следующие команды выполняются **на VPS, не в Codespaces и не на Mac**. Нужен root; если вы вошли другим пользователем, сначала выполните `sudo -i`.

На новом сервере:

```bash
apt-get update
apt-get install -y git nano
git clone https://github.com/5yb6wsf8vv-gif/karate_kiokushinkai.git /opt/kyokushin
cd /opt/kyokushin
bash deploy/vps/install-docker.sh
cp deploy/vps/.env.example deploy/vps/.env
nano deploy/vps/.env
```

Если репозиторий уже находится в `/opt/kyokushin`, не клонируйте поверх него: перейдите в него и выполните `git pull --ff-only`. Если репозиторий закрытый, сначала настройте доступ через deploy key; не вставляйте токен в URL команды.

Заполните два значения в `.env`:

```dotenv
DUEL_HOST=ваше-имя.duckdns.org
ACME_EMAIL=ваша-почта@gmail.com
```

В `DUEL_HOST` должно быть реальное латинское имя, без `https://`, `/health` и пробелов. Почта нужна для регистрации HTTPS-сертификата; сервис рассылки писем не требуется. В nano: Ctrl+O → Enter → Ctrl+X.

Затем:

```bash
./deploy/vps/compose.sh config --quiet
./deploy/vps/compose.sh up -d --build
./deploy/vps/compose.sh ps
./deploy/vps/compose.sh logs --tail=50 caddy api
```

Первый запуск загружает образы Node и Caddy и получает сертификат. Проверьте в браузере (включая инкогнито):

```text
https://ВАШ-ПОДДОМЕН.duckdns.org/health
```

Ожидаемый JSON:

```json
{"ok":true,"service":"kyokushin-duel","version":1}
```

Консоль можно закрыть: контейнеры работают в фоне. Установщик включает Docker при загрузке ОС, а `restart: unless-stopped` запускает контейнеры после перезагрузки VPS и после аварийного завершения процесса. Упавший процесс перезапускается; один статус `unhealthy` без завершения процесса сам по себе не вызывает перезапуск Docker.

## 4. Подключить сайт для всех игроков

В GitHub откройте репозиторий → Settings → Secrets and variables → Actions → **Variables** → New repository variable:

- Name: `VITE_API_URL`
- Value: `https://ВАШ-ПОДДОМЕН.duckdns.org` — без `/health`.

Это публичный адрес, не секрет. Затем Actions → Publish GitHub Pages → Run workflow. После успешной публикации откройте сайт или PWA и примените «Обновить приложение», если есть предложение обновления.

Новая версия автоматически берёт постоянный адрес из `VITE_API_URL`, даже если на устройстве ранее сохранился старый адрес Codespaces. Игрокам не нужно вводить сервер вручную. Сеансы прежнего сервера не переносятся: создайте новую комнату и новое приглашение.

Проверьте игру двумя устройствами (например, компьютер + телефон с мобильным интернетом): создание комнаты, вход по приглашению после настройки имени/курса, 10 заданий, итог поединка. После этого остановите Codespaces и убедитесь, что новая комната всё ещё создаётся на VPS. Это проверяет независимость от Codespaces.

## 5. Обслуживание

Обновлять код сервера следует между поединками:

```bash
cd /opt/kyokushin
git pull --ff-only
./deploy/vps/compose.sh up -d --build
./deploy/vps/compose.sh ps
```

Просмотр журналов: `./deploy/vps/compose.sh logs --tail=100 api caddy`.
Перезапуск API: `./deploy/vps/compose.sh restart api`.
Остановка: `./deploy/vps/compose.sh stop` — после явной остановки автозапуск контейнеров отключён до следующего `up -d`/`start`.

Комнаты хранятся в памяти **одного** процесса. Перезапуск, обновление и сбой завершают текущие комнаты; локальный учебный прогресс не затрагивается. Не запускайте несколько копий API и не включайте балансировку между ними без общего хранилища комнат. Caddy хранит сертификаты в Docker volumes; не удаляйте их через `down -v` при обычном обновлении. Для слежения за доступностью можно подключить внешний мониторинг `/health` у выбранного сервиса.

`TRUST_PROXY=true` включён только для этой схемы: порт API не публикуется наружу, запросы приходят через единственный Caddy. Так ограничения частоты работают по адресам игроков, а не по одному адресу прокси. При запуске Node напрямую в интернете не включайте TRUST_PROXY.

Готовые конфигурации и локальные проверки не подтверждают работу вашего домена и оплату VPS. Реальную HTTPS-проверку можно выполнить только после создания сервера, настройки DNS и запуска команд выше.
