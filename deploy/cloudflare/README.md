# Поединки на Cloudflare Workers + Durable Objects

Сайт/PWA остаются на GitHub Pages. Cloudflare обслуживает только API поединков. VPS, собственный домен и работающий Codespaces после публикации не нужны. Адрес сервера выдаётся на `workers.dev` с HTTPS.

Используются SQLite-backed Durable Objects (`new_sqlite_classes`), совместимые с Workers Free в пределах его квот. Это не обещание неограниченного бесплатного хостинга или гарантии доступности: проверьте условия и квоты в своём кабинете Cloudflare. При исчерпании бесплатной квоты поединки могут перестать работать до её сброса. Платный тариф для этой конфигурации включать не требуется; если кабинет предлагает обязательное платное подключение, сначала проверьте название ресурса, тариф и текст ошибки.

## Публикация через кабинет Cloudflare и GitHub

1. Зарегистрируйтесь на https://dash.cloudflare.com/sign-up и подтвердите почту.
2. В меню откройте **Workers & Pages** (в некоторых версиях интерфейса внутри **Compute & AI**) → **Create application / Создать приложение** → импорт Git-репозитория.
3. Подключите GitHub и разрешите доступ к репозиторию `5yb6wsf8vv-gif/karate_kiokushinkai`.
4. Создайте **Worker** со следующими настройками:

| Поле | Значение |
| --- | --- |
| Имя Worker / Project name | `kyokushin-duel` |
| Production branch | `main` |
| Root directory | корень репозитория `/` |
| Build command | `npm run cloudflare:check` |
| Deploy command | `npm run cloudflare:deploy` |
| Node.js version, если предлагается | 22 или 24 |

Для сервера не нужны `dist`, сборка Vite и режим Pages. Команда `cloudflare:deploy` явно указывает `deploy/cloudflare/wrangler.jsonc` и создаёт binding `ROOMS`, SQLite Durable Object `DuelRoom`, миграцию `v1` и ограничения частоты. Не удаляйте миграцию `v1` после первого развёртывания. Если мастер создал другое имя Worker, измените его на `kyokushin-duel`, чтобы оно совпало с конфигурацией.

5. Нажмите **Deploy / Опубликовать** и дождитесь успешного завершения. При первом использовании Workers кабинет может предложить выбрать свободный поддомен аккаунта.
6. Скопируйте адрес вида `https://kyokushin-duel.ВАШ-ПОДДОМЕН.workers.dev`. Это пример формата, не заранее работающая ссылка.
7. Откройте его с `/health`. Ожидается JSON с `ok: true`, `service: "kyokushin-duel"`, `version: 1`, `pollIntervalMs: 2500`.

Если импорт из GitHub недоступен в вашем интерфейсе, используйте CLI-вариант ниже. Cloudflare сам управляет HTTPS; настраивать DNS и покупать домен не нужно.

## Подключить опубликованный сайт ко всем игрокам

В production-сборке уже задан адрес `https://kyokushin-duel.5yb6wsf8vv.workers.dev`, полученный из успешной публикации владельца аккаунта. Если GitHub Variable `VITE_API_URL` не задана, приложение использует этот адрес автоматически. Существующая переменная имеет приоритет: при переносе с другого сервера обновите её. Локальная разработка по-прежнему позволяет вводить адрес вручную.

Следующие действия нужны для переопределения адреса:

В GitHub откройте репозиторий → **Settings → Secrets and variables → Actions → Variables → New repository variable**:

- Name: `VITE_API_URL`
- Value: HTTPS-адрес Worker **без `/health`**.

Это публичный адрес, не секретный ключ. Затем **Actions → Publish GitHub Pages → Run workflow**. После успешной публикации обновите сайт; в установленном PWA примените «Обновить приложение», если появилось предложение.

Форма поединков подключается к `VITE_API_URL` автоматически, заменяя ранее сохранённый адрес Codespaces. Создайте **новую** комнату и отправьте новое приглашение сопернику. Старые комнаты из Node-сервера в Cloudflare не переносятся. Проверьте полный поединок на двух устройствах и создание комнаты при остановленном Codespaces.

## Публикация через CLI (альтернатива)

В Codespaces/локальном терминале Node 22+:

```bash
git pull --ff-only
npm ci
npx wrangler login
npm run cloudflare:deploy
```

`wrangler login` открывает авторизацию в браузере. В удалённой среде обратный переход на localhost может потребовать перенаправить порт авторизации; если переход не работает, используйте импорт репозитория через кабинет. Альтернативно можно настроить собственные `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` в секретах среды, но не публиковать их в коде/чате. Файл конфигурации не содержит токенов. После успешного deploy скопируйте выданный адрес `workers.dev` в GitHub Variable `VITE_API_URL` и повторно опубликуйте Pages.

## Как работают комнаты и ограничения

- Каждая комната — отдельный именованный Durable Object. Запросы обрабатываются последовательно, поэтому из двух правильных ответов на один раунд очко получает один игрок.
- Состояние, токены и результат сохраняются в хранилище объекта. Повторное создание экземпляра объекта не стирает комнату. Изменение структуры данных в будущих версиях требует совместимой миграции.
- 10 общих заданий, 20 секунд на ответ, одна отправка, очко за первый правильный ответ. Итог определяется количеством очков; равный счёт означает ничью. Схемы остаются учебными, с прежним предупреждением о проверке тренером.
- Максимальный срок комнаты — 30 минут с создания, включая ожидание соперника. Alarm удаляет состояние, когда срок истёк. Просроченную комнату нужно создать заново.
- Состояние опрашивается каждые 2,5 секунды для сокращения расходов. Перед новым раундом есть 4 секунды подготовки, чтобы оба клиента успели получить задание. Таймер ответа работает локально по времени сервера. После ошибки 401/404 и после завершения матча лишние опросы останавливаются.
- CORS разрешает только `https://5yb6wsf8vv-gif.github.io`; localhost включён лишь в `cloudflare:dev`. Токены игроков идут в Authorization и не входят в ссылку-приглашение.
- Ограничители запросов/создания комнат уменьшают случайный расход квоты. Они не гарантируют защиту бесплатного публичного сервиса от распределённой нагрузки.
- Worker не обслуживает почтовую/VK-регистрацию: профиль, XP и скины остаются локальными. Сервер проверяет допустимый ID аватарки, но не подтверждает локальную покупку.

В кабинете Cloudflare следите за **Workers и Durable Objects → Usage / Metrics**. Не добавляйте серверный адрес в сервисы постоянного «прогрева»: они тратят квоту. Worker вызывается по запросам игроков, а не требует круглосуточно работающей виртуальной машины.

## Проверки и локальная разработка

```bash
npm test
npm run cloudflare:check
npm run cloudflare:dev
```

`cloudflare:check` выполняет dry-run, ничего не публикует и не требует токена. `cloudflare:dev` запускает настоящий локальный runtime workerd с SQLite Durable Objects на `http://127.0.0.1:8787`. Данные локальной среды находятся в `.wrangler` и исключены из Git.

Проверка двух браузеров (desktop/mobile, реальный workerd, полный матч 7:3, приглашение и одна попытка):

```bash
npm run test:cloudflare
```

Локальные тесты не означают, что сервис уже опубликован в вашем аккаунте: доступность публичного `workers.dev`, текущий бесплатный тариф и квоты проверяются после реального deploy владельцем аккаунта.
